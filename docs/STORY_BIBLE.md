# Mara's managed Story Bible

Opening a saved draft enables persistent automatic Bible maintenance. The backend checks watched books every five seconds, waits for active revisions to finish, and refreshes changed source fragments even after the browser closes. Watch subscriptions survive service restarts. The Story Bible button shows progress, source quotes, chapter coverage, provisional draft observations, and separate author decisions. Adding a chapter file creates a shared book if necessary and links the upload to it. No chapter is silently approved or rewritten by Bible maintenance.

`lib/managed-story-bible.mjs` extracts structured notes using the configured studio quality (Sol, xhigh, pro). The extraction includes a short exact source quote for every note. Unsupported quotes and invalid output are rejected. Protected passages are excluded. This checks provenance, not semantic infallibility: Mara must preserve uncertainty and ask about contradictions. Explicit author decisions outrank inferred notes.

Completed fragment notes persist in SQLite keyed by content, chapter identity, title, and extraction version. Changed sources cannot reuse outdated notes; unchanged fragments do not trigger another model call. A failed run needs explicit Retry. An interrupted watched run resumes from completed fragments after a service restart. Original prose, edited prose, approved book versions, and author notes remain separate. Deleting an imported project removes its generated fragment notes and fences late cache writes.

Mara's editing and voice context includes the shared Bible with chapter references, draft/approved status, and explicit coverage. Context has a 40 KB budget with omitted counts; source quotes are displayed in the Bible but are not sent as earlier-chapter prose to editing. Current chapter requests refresh only that chapter, use available earlier summaries, and disclose missing coverage. The background Bible refresh builds the rest. Whole-book requests refresh the complete linked Bible before editing. No editing scope is expanded by Bible access.

Validation: writing-studio tests cover cross-file continuity, persistence, changed-source invalidation, source validation, author-note preservation, explicit retry, interrupted refresh, protected passages, and chapter isolation. The mocked HTTP integration suite covers authenticated Bible sync/read, shared sources, unchanged-cache reuse, deletion cleanup, and existing editorial flows. Browser checks cover automatic shared-book creation on Add chapter and desktop/mobile display. No production manuscript or paid generation is used in these checks.

Saved manual edits, model revisions, Undo, chapter structure changes, and newly linked files are detected from the current source fingerprint rather than relying on browser notifications. Unchanged sources make no model call. Failed extraction remains visibly failed until explicit Retry or a new source revision; the periodic check does not create an automatic paid retry loop.
